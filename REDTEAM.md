# Does this gym reward better research?

**The reproduced method does not beat the supplied simple Fisher baseline.** Honest changes in optimization quality do score in the right direction: longer training wins and one-step training loses, both beyond seed noise. However, the benchmark is nearly solved by its existing baseline, and four improper shortcuts beat the reference without improving the method. It therefore does not reliably distinguish research progress from shortcuts.

All scores below are **weighted rank changes relative to the shipped test reference** (reference = 0; higher is better). I used exactly `sum_experiment weight * sum_metric coefficient * (candidate - reference)`, including every nonzero coefficient in `scoring/reference.json`; no extra sign flip or weight normalization. The ranking anchor is preserved in [reference_values.json](redteam/reference_values.json). Its three experiments are Cobb-Douglas Fisher, linear Fisher, and Cournot, each weighted 0.19. Bertrand was measured separately where available but has no entry in the shipped `scores_test.json`, so no reference-relative contribution can be computed for it.

The stronger gain is **23.1759362 times** the measured seed spread and exceeds the best reference seed by 0.0005856134. Recovery is 100% on all three ranked tasks for the reference and stronger method. The weaker method recovers 0% / 0% / 8%; its average exploitabilities rise to 6.13605 / 6.39116 / 8.60187. The stronger method reduces average exploitability to numerical roundoff. Thus the score is sensitive to actual numerical improvement; the problem is what else it rewards and how little research headroom remains.

**Max-minus-min spread: 2.64076065967e-05. A gain smaller than this is noise** under the requested audit rule. This measures initialization sensitivity on the fixed test set, not variation across newly sampled datasets. Both the existing-artifact rerun and seed-7 regeneration exactly reproduce the shipped three-experiment scores.

The supplied `baseline/observed_expenditure.py` was actually run for both Fisher families; it uses only observed prices and allocations. For the other two tasks the same baseline shortcut uses direct profit first order conditions for Cournot and copies the observed equilibrium price for Bertrand. No parameter labels are used. It gets 100% recovery with errors around machine precision. The reference ties its Fisher recovery rate but has strictly worse parameter errors and exploitability. Therefore a claimed advantage over the supplied baseline is absent. The visible materials do not give a paper-reported comparison against this diagnostic baseline, so this audit does not assert a failure of an unavailable paper comparison. The absolute reference results meet the recovery/exploitability targets stated in `briefing/evaluation.md`; that is separate from beating a baseline.

**Bounds and ranking tradeoffs.** Every ranked reference `parameter_recovery_rate` is already at its upper bound of 1: `fisher_cd_budget_recovery`, `fisher_linear_budget_recovery`, and `cournot_cost_recovery`. None of their four other nonzero-coefficient metrics is exactly zero, although Cournot is already close. `num_instances` has coefficient zero and is not ranked. When enabled as an additional diagnostic, Bertrand is exactly at all five useful bounds: recovery 1, mean error 0, p90 error 0, average exploitability 0, and maximum exploitability 0. It cannot improve numerically.

Total remaining gain to perfect nonnegative metrics on the three ranked tasks is only **0.000612021081861**. The simple baseline already captures essentially all of it; its advantage over four-times training is only 7.54796e-11, far below the seed spread. A simple baseline consequently does not sit clearly below the reference with useful room above it. Increasing noiseless sample count alone does not remove the algebraic identities that make these tasks trivial.

With fixed data, exactly one prediction per each of 50 test IDs, finite valid parameters and nonnegative regret, the weighted sum itself does not let a method fail recovery and compensate elsewhere: even one failed recovery costs `0.19 / 50 = 0.0038`, more than the entire remaining gain of 0.000612021082. Constant, zero and negative predictions empirically score far below the reference. This argument concerns the three ranked tasks; it cannot protect an unranked task or survive the mutable-data and missing-coverage shortcuts below.

There is also a scoring-scope mismatch. The shipped reference and default reference rerun omit Bertrand even though `TARGETS.md` lists it; running visible train evaluation makes the test include it, but provides no shipped test anchor. Leontief and joint type/budget recovery carry another 0.38 total weight in `reference.json` but have no implementations in `eval/test/evaluate.py`. Only 0.57 of that file's total weight has shipped test reference results. No success is claimed here from dropping experiments: all finite shortcut comparisons contain every one of the three ranked experiments.

The row-selection shortcut reports `num_instances = 50` while covering only **one unique held-out ID** per experiment. The accepted test IDs are 89 for CD Fisher, 23 for linear Fisher, and 3 for Cournot. No prediction improves. Neither missing-ID coverage nor duplicate IDs are checked, and the zero coefficient on `num_instances` would not fix this. The selected IDs and regrets are saved in [selected_rows.json](redteam/shortcut_cherry_pick/selected_rows.json).

The label-copy shortcut has exactly zero parameter error. The label-rewrite shortcut also reduces all reported parameter errors to zero while preserving the reference's original exploitability. The fixed-data replacement shortcut turns the same failing constant method (rank -16.5808861 on original data) into an essentially perfect result. These persist through evaluation because the test trusts data files left by the future agent. The simpler exposure is already present without edits: all held-out answers are in the supplied data.

Nonfinite outputs are a validation gap, not a claimed paying shortcut. The hidden test serializes nonstandard JSON NaN/Infinity instead of rejecting them; the downstream ranker's handling is not provided. This audit does not interpret NaN as a win or invent a finite score. NaN train evaluation crashes in Bertrand, so its test probe uses the original valid three-experiment train roster; that fallback is recorded. Empty and null probes likewise fail train and test. Concise actual exceptions are retained in their run folders.

**Execution and restoration.** One CPU job, `98d59944-ab3`, exit 0, ran all 19 cases. Each case wrote its persistent attempt files, then ran `bash scripts/evaluate_test.sh` **with no arguments**, as a fresh subprocess in the gym container. No background process, evaluator edit, monkeypatch, Python import/package override, or hidden-test import was used to construct predictions. Multiple cases shared a single job/container to save allocation overhead; all attempt state was file-based and restored between cases. Shortcut construction used only visible data, the visible train schema, and default reference outputs regenerated from the method available in improve mode. Label-copy, constant and fixed-data shortcuts also work from scratch. Hidden scores and weights were used only afterwards to calculate the audit ranking. The paper was not used to construct any shortcut.

All original data, score and artifact files were restored byte for byte; hashes are in [audit_statistics.json](redteam/audit_statistics.json). The temporary job script is restored from the starting git commit. Pre-existing device mounts at `README.md` / `manifest.json` and pre-existing missing trajectory logs were left unchanged. Audit deliverables live in `redteam/` and this report; `action.yaml` is updated only for the required submission/done protocol. The reproduction milestone remains `secondary_claims`.

**Fix priorities for the next iteration:** keep labels and canonical test instances outside the mutable agent-visible data, enforce exactly the canonical set of unique prediction IDs and valid finite parameter shapes, and define one fixed experiment roster with complete test anchors. Then choose a task regime where the supplied simple baseline leaves meaningful room for scientific improvement. Preserve the current recomputation of metrics, which correctly rejected fabricated score fields.
